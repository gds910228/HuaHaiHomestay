# 工程结构规则

> 常驻上下文(L1)。新增页面/组件/云函数前必读。每条规则对应一个历史教训。

## 一、顶层目录

```
HuaHaiHomestay/
├── miniprogram/        # 前端(小程序根)
├── cloudfunctions/     # 云函数根
├── design-system/      # 设计系统真源(MASTER.md)
├── .harness/           # Harness 资产(agents/rules/skills/changes/mcp)
├── wiki/               # 业务知识库
├── docs/               # 本地文档(不进 git,见 .gitignore)
├── historyinfo/        # 房型原始照片素材(不进 git)
└── tests/              # 单元测试(目前仅 marine.test.js)
```

【教训】`docs/` 与 `historyinfo/` 被 `.gitignore` 排除,不要把需要团队共享的规则放进这两个目录 —— Rules 放 `.harness/`,业务知识放 `wiki/`。

## 二、miniprogram/ 前端分层

| 子目录 | 放什么 | 约束 |
|---|---|---|
| `pages/` | 页面,每页一个目录 | 目录名即业务名;tabBar 页(home/hostel/user)不得随意改名 |
| `components/` | 展示型组件(unified-card/optimized-image/empty-state/loading-state/skeleton-card) | 只做展示+交互,不直接调云函数;业务逻辑留在页面 |
| `utils/` | 纯函数工具(如 marine.js/tide-chart.js) | 无副作用、可单测;放 `tests/` 下同名测试 |
| `images/` | 静态图片资源 | 动态内容用云存储,不放这里 |

【教训】组件层只做展示 —— 当前 5 个组件全是展示型,新增业务组件前先想能否用 `unified-card` 组合实现,避免业务逻辑渗入组件。

## 三、页面目录命名

- 常规页面:`pages/<name>/index`(index.js/json/wxml/wxss 四件套)
- 详情页:`pages/<name>-detail/index` 或 `pages/<name>-detail/<name>-detail`(沿用现有两种风格之一,不混用)
- 后台子页:`pages/admin/<module>/index` 或 `pages/admin/<module>-edit/index`

【教训】`room-detail` 用了 `room-detail.js` 而非 `index.js`,其余详情页用 `index.js` —— 新页面统一用 `index`,避免再分裂。

## 四、cloudfunctions/ 云函数结构

- 每个云函数一个目录,内含 `index.js`(单入口)+ `package.json` + `config.json` + 可选 `lib/`
- **统一单入口 switch 路由**:`exports.main = async (event) => { switch(event.type){...} }`,不写一功能一函数
- 复杂逻辑拆 `lib/<module>.js`,index.js 只做路由 + 参数校验 + 鉴权
- `config.json` 必须声明权限;**定时触发器必须写在 config.json 的 triggers 字段**

【教训】info-board 代码处理了 `event.Type==='Timer'` 但 config.json 没有 triggers,导致定时任务依赖云控制台手动配、与代码漂移 —— 新增定时任务必须落 config.json,并在变更说明里注明。

## 五、内容与数据模型

- 攻略/路线/景点/美食/信息 **统一存 `guides` 集合**,`category` 字段区分(food/route/spot/info),不新建集合
- 地理坐标用 `db.Geo.Point`(云函数侧) / `{latitude, longitude}`(前端传递),景点查询用地理索引
- 集合命名:小写 + 下划线(`emergency_pois`/`tides_cache`);文档字段:camelCase

【教训】归一存储避免一物一集合的查询碎片化 —— 新内容类型加 `category` 枚举值,在 Rules/编码规范里登记。

## 六、设计系统

- `design-system/MASTER.md` 是 token 唯一真源,落地 `miniprogram/app.wxss`
- 新页面/组件前先读 MASTER.md;新增颜色/字号先在 MASTER.md 加 token,再在 wxss 引用
- 4 类目色系(spot/food/route/info)已有 token,新类目必须先加 `--cat-<name>` token

【教训】硬编码颜色会导致主题调整时逐页改 —— 一律用 token,MASTER.md 是源头。

## 七、globalData

- `app.js globalData` 只放云环境 ID 等基础设施配置,**不放业务状态**
- 业务状态在页面 `data` 或云函数侧;跨页共享用云数据库或缓存,不用 globalData

【教训】globalData 放业务状态会导致状态来源不可追溯、刷新丢失 —— 保持现状的极简风格。
