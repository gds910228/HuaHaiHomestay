# 项目编码规范

> 常驻上下文(L1)。写/改代码前必读。每条硬性约束对应一个历史教训,标注【教训】。

## 一、硬性约束(必守)

### 1. 价格字段
- 优先 `fixedPrice`:**元的整数**(如 538、868),不要用分
- 兼容旧结构 `price: { low, high }`(淡/旺季);新数据写 `fixedPrice`
- 排序/展示必须兼容两种:`const p = x.fixedPrice ?? (x.price && x.price.low) ?? 0`
【教训】价格结构演进过一次,排序逻辑漏兼容会导致房型乱序(huahai 已修)。

### 2. 时间字段
- `createTime`/`updateTime` 用 `db.serverDate()` 写入(云函数侧),前端展示用 `wx` 时间 API 格式化
- 不要用本地 `new Date()` 写库,会有时区/时钟漂移

### 3. 位置字段
- 前端定位统一 `wx.getFuzzyLocation`(**不**用 `wx.getLocation`),声明 `scope.userFuzzyLocation`
- `app.json` 的 `permission`/`requiredPrivateInfos` 已配 `getFuzzyLocation`/`chooseLocation`,新增定位能力前先确认类目权限
【教训】本项目类目(工具/天气/资讯)下 getLocation 不可申请,会被拒;统一模糊定位。

### 4. 集合创建
- 写新集合前必须 `ensureCollection(db, name)`:显式 `createCollection`,catch errCode -502002(已存在)
- 不要假设 `db.add` 会自动建集合 —— **它不会**
【教训】info-board 因未显式建集合导致首次写入失败,后补 ensureCollection。

### 5. 密码与密钥
- 管理密码走云函数 env var `ADMIN_PASSWORD`,校验用定长比较(防时序攻击)
- 第三方 KEY(AMAP_KEY/QWEATHER_KEY/WORLDTIDES_KEY)同样走 env var
- **严禁**硬编码密码/KEY 到代码(仓库已公开)
【教训】仓库公开,密码入码即泄露;已统一迁出到 env var。

### 6. 富文本图片
- 富文本内 `cloud://` 图片链接有效期 2h,详情页渲染前需 `refreshContentImages` 续签 `getTempFileURL`
- 新富文本字段同理:展示前检查并续签
【教训】cloud:// 链接过期会导致图片 404,详情页必须续签。

### 7. 云存储清理
- 云存储无 listFiles API,孤儿文件清理走「控制台导出文件清单 + 云函数 diff」两步
- 不要尝试用 SDK 列举全量文件
【教训】huahai 已实现 scanGuideImages/computeOrphans/cleanupFiles,沿用此模式。

### 8. 定时触发器
- 定时任务必须写进云函数 `config.json` 的 `triggers`,**不**只靠云控制台手动配
- 代码内 `event.Type === 'Timer'` 分支要和 config.json 一一对应
【教训】info-board 触发器未落 config 导致漂移隐患。

### 9. 审核合规
- 用户可见文案中**不**用"游玩路线""旅行社""预订""下单"等旅游服务/交易类词
- 路线类目对外称"南澳玩法/玩法",代码标识符保留 `route`
【教训】"游玩路线"曾被判旅行社服务拒审;文案合规先于开发。

## 二、命名规范

| 对象 | 规范 | 示例 |
|---|---|---|
| 变量/函数 | camelCase | `getNearbySpots` |
| 组件 | PascalCase 目录 | `UnifiedCard` |
| 页面目录 | kebab-case | `guide-detail` |
| 集合名 | 小写+下划线 | `emergency_pois` |
| 文档字段 | camelCase | `createTime` |
| 云函数 event.type | camelCase | `getGuideDetail` |

## 三、注释规范

- 云函数每个 `case` 顶上一行注释说明用途
- `ensureCollection`、`checkAdminPassword`、`refreshContentImages` 等已有 helper,**复用不重写**,新代码引用即可
- 踩坑点(如"此处不能用 getLocation")必须就近注释,后人/AI 不再重踩

## 四、异常处理

- 云函数返回结构统一:`{ success: boolean, data? | errMsg? }`
- 聚合接口(如 info-board 的 `all`)用 `Promise.allSettled`,部分失败不影响其他模块
- 集合创建/写入失败要 `console.warn` 记录,不静默吞错

## 五、状态管理

- 页面状态 `this.setData()`,父子用 properties + 事件
- 不在 globalData 放业务状态(见工程结构规则)
